## Reproduced failures and corrections

Before the visibility fix, the new ordinary-dialog scenario received `Mission in progress` after Guide→background/return→close, where it required `Mission paused`. The implementation invalidates the remembered resume intent on hidden and checks visibility when closing. Both local engines pass the regression after the fix.

The enlarged-content probe initially reported document widths 426/428 for a 390 px viewport. The unshrinkable destination group extended beyond the page; telemetry clipped the pause controls. Allowing the location to shrink/cap its width and wrapping mobile telemetry fixes actual reachability rather than hiding overflow. The same scenario passes both local engines. CSS zoom is a layout stress test, not native text-size evidence.

The first full local run found a stale old portrait expectation (`ranger.png` versus the correct `ranger.webp`). The full local matrix passed 64 of 66 checks, with that same stale URL expectation failing once per engine. The exact CSS URL assertion was corrected; a fresh four-check Chromium/WebKit run passed both corrected scenarios and both Canyon complete-mission checks with the strengthened ledger assertions. The clean final Linux matrix covers all 99 checks. No skip, extra security flag, removed assertion or timeout relaxation was used for that correction. New complete-mission scenarios have their own 150-second budgets because they exercise full real-time games; existing 45-second cases keep their limits.
